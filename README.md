# Agent Skills Repository

本仓库用于存放和管理自用的 AI Agent 技能（Skills）。这些技能旨在提升开发效率，涵盖了自动化编码、CI 诊断、前端审查及打包自动化等多个场景。

## 技能列表汇总

| 技能名称 | 目录 | 核心功能 | 适用模型 |
| :--- | :--- | :--- | :--- |
| **智慧编码 (AI Coding)** | `ai-coding` | 全自动开发流程，从需求分析到 PR 合并的闭环自动化。 | 通用 |
| **Woodpecker CI 诊断** | `woodpecker-ci-triage` | 自动检查 CI 状态，失败时拉取并分析日志定位根因。 | 通用 |
| **前端 PR 审查** | `pr-review-frontend` | 针对前端 PR 的一次性深度代码质量评审。 | 通用 |
| **前端探索性测试** | `frontend-exploratory-testing` | 面向浏览器的前端探索性测试、证据采集与 Issue 输出。 | 通用 |
| **Argos 视觉优化** | `argos-visual-timing` | 优化 Argos/Playwright 截图时机，解决截图太早/太晚问题。 | 通用 |
| **打包脚本专家** | `build-scripts` | Android (React Native) 打包自动化，确保环境纯净与 100% 成功率。 | 通用 |
| **硬盘清理分析** | `disk-cleanup-analysis` | macOS 硬盘占用分析与安全清理，分级识别可重建缓存、孤儿目录、僵尸文件与 TM 快照。 | 通用 |
| **交付成果验证** | `verifying-delegated-work` | 验收他人（含其他 Agent）交付的成果：数字自己重跑、守卫用变异证明。 | 通用 |

## 详细技能说明

### 🤖 智慧编码 (`ai-coding`)
- **定位**：全自动执行者，而非单纯的提醒者。
- **架构**：采用模块化设计，核心逻辑已封装至 `scripts/`（自检、提交、监控），配置与需求文档采用 `templates/` 管理。
- **工作流**：状态自检 -> 环境初始化 -> 编码与测试 -> 资源清理 -> 创建 PR -> **持续监控循环**。
- **核心特色**：具备“零打扰”原则，监控脚本会自动修复 CI 失败、解决代码冲突并响应 Review 反馈。

### 🪵 Woodpecker CI 诊断 (`woodpecker-ci-triage`)
- **定位**：解决“为什么 CI 挂了”的快速响应专家。
- **功能**：整合了 Codex、Gemini、Kimi 多个版本的优点，实现模型无关的自动化诊断。
- **常见模式**：内置了针对依赖超时、编译失败、权限错误等常见故障的速查表。

### 🔍 前端 PR 审查 (`pr-review-frontend`)
- **定位**：一次性、深度的前端代码评审。
- **自包含规则**：内置 8 大核心审查视角（在 `rules/` 目录下），包含通用规范、JS 逻辑、静默失败猎手等，不再依赖外部路径。
- **输出**：生成高质量的中文评审报告，重点突出阻塞性问题。

### 🧪 前端探索性测试 (`frontend-exploratory-testing`)
- **定位**：面向浏览器的探索性测试与 Issue 产出。
- **流程**：先列测试重点，再主动点击、输入、切换、缩放和观察控制台，最后基于 open Issue 做去重。
- **证据策略**：对重复问题不仅比标题，还要比截图、录屏和报错栈；高度相似则跳过，不相似则补充证据后再提。

### 📸 Argos 视觉优化 (`argos-visual-timing`)
- **定位**：提升视觉回归测试的稳定性。
- **策略**：将截图分为“早截”（捕捉入口态）和“晚截”（等待内容锚点稳定），减少对固定 `waitForTimeout` 的依赖。
- **目标**：消除重复态截图，确保 Argos Diff 的有效性。

### 📦 打包脚本专家 (`build-scripts`)
- **定位**：严苛模式下的 Android/RN 打包自动化。
- **原则**：零污染（打包后彻底还原）、物理隔离（清理 node_modules）、全量覆写（保证环境一致性）。
- **能力**：包含 NDK 崩溃修复、MMKV 镜像优化、AndroidX 锁定等一系列黄金实践。

### 🧹 硬盘清理分析 (`disk-cleanup-analysis`)
- **定位**：macOS 用户级硬盘分析与安全清理，先分析、再分级、确认后删除。
- **工具链**：mole（缓存/孤儿/项目产物扫描）、du、lsof、df、tmutil、diskutil。
- **分类经验**：可重建缓存（Yarn v1 实为 `~/Library/Caches/Yarn/v6`、npm、CocoaPods、Playwright 等）、应用更新残留（ShipIt/UpdatePackages）、孤儿目录三步确认法（lsof + which + LaunchAgent）、僵尸文件（`lsof +L1` 找占用进程）、TM 本地快照。
- **核心亮点**：TM 本地快照可免 sudo 用 `diskutil apfs deleteSnapshot` 批量删除（tmutil 在 macOS 26 失效），实测一次释放 30G+；删除后 `df` 不涨优先排查快照。


### ✅ 交付成果验证 (`verifying-delegated-work`)
- **定位**：接手别人（尤其是其他 Agent）「已完成」的分支时，防止把转述当验证。
- **两条纪律**：① 对方报的测试数/通过率/lint 结果**自己重跑**再引用，否则明确标注「未跑、采信作者」；② 「测试是真守卫」必须用**变异证明**——把修复改回缺陷态，断言必须变红。
- **描述口径**：`description` 只写触发条件、不概述流程（`writing-skills` 明确警告过：描述里概述流程会让模型照描述走而跳过正文）。
- **实测由来**：无 skill 的基线评审明说「我这边不需要再跑一遍全量」且全程未做变异；带 skill 后同一场景下自己重跑了全部数字、做了 14 条变异，并靠变异挖出一条「141 条测试全绿但守卫维度缺失」的真问题。

## 使用指南
每个技能目录下均包含一个 `SKILL.md`，其中详细说明了该技能的触发场景、环境变量要求及具体工作流。你可以根据需要将特定技能加载到你的 AI 助手（如 Gemini CLI, Claude Desktop 等）中使用。
